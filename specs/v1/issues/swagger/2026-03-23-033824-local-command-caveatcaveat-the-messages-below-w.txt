     Fix Swagger UI Showing Petstore Instead of Project API

     Context

     The docs.routes.ts redirects to /docs/index.html?url=/docs/spec, intending
     to load openapi.yaml. However, swagger-ui-dist ships with a
     swagger-initializer.js that has the Petstore URL hardcoded. That
     initializer runs on page load and overrides whatever ?url= query parameter
     was passed, so users see the Petstore API instead of the IAM spec.

     The openapi.yaml itself is already fully correct and complete for this
     project — it just never gets loaded.

     Root Cause

     swagger-ui-dist/swagger-initializer.js:
     window.onload = function() {
       window.ui = SwaggerUIBundle({
         url: "https://petstore.swagger.io/v2/swagger.json",  // ← hardcoded, 
     overrides ?url= param
         ...
       })
     }

     Fix

     Serve a custom swagger-initializer.js from the Express router before the
     static middleware serves the dist version. This custom file explicitly sets
      url: "/docs/spec" so Swagger UI always loads the project's spec.

     Files to modify

     src/routes/docs.routes.ts — add one route before
     router.use(express.static(...)):

     router.get("/swagger-initializer.js", (_req, res) => {
       res.type("application/javascript");
       res.send(`
     window.onload = function() {
       window.ui = SwaggerUIBundle({
         url: "/docs/spec",
         dom_id: '#swagger-ui',
         presets: [SwaggerUIBundle.presets.apis, SwaggerUIStandalonePreset],
         layout: "StandaloneLayout"
       });
     };
       `.trim());
     });

     Route order matters: Express matches routes top-to-bottom, so this custom
     handler fires before express.static(absolutePath()) would serve the dist
     version.

     No other files need to change

     - openapi.yaml is already correct
     - app.ts mounts /docs router unchanged
     - Tests in docs.routes.test.ts may need a new assertion for the new route

     Verification

     1. docker-compose up (or npm run dev)
     2. Navigate to http://localhost:3000/docs/ — should redirect to Swagger UI
     showing IAM Microservice API, not Petstore
     3. Confirm all 11 endpoints are visible under Auth and Users tags
     4. Run npm test to ensure existing docs route tests still pass
